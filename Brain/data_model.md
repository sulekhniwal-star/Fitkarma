# FitKarma — Data Model (Supabase Postgres)

Every table below carries `id uuid primary key default gen_random_uuid()`, `created_at timestamptz default now()`, and `updated_at timestamptz default now()` unless noted. Every user-data table carries `user_id uuid references auth.users(id) on delete cascade` and an RLS policy of the shape `using (auth.uid() = user_id)` for select/insert/update/delete, unless noted otherwise.

## Core identity
- **profiles** — demographics, BMI inputs, onboarding state.
- **dosha_scores** — Vata/Pitta/Kapha scoring results, versioned by `assessed_at`.
- **cycle_tracking** — women's health cycle data, PCOS flags (sensitive — encrypt at rest via Supabase Vault or column-level pgcrypto if required by legal review).

## Daily intelligence / readiness (P2–P3)
- **readiness_scores** — daily 3-tier confidence score, inputs snapshot.
- **dip_cache** — cached Daily Intelligence Package components, TTL column, keyed by `user_id, date`.
- **coach_sessions** / **coach_messages** — AI coaching conversation history.

## Health tracking (P4) — append-only, no update conflicts
- **wearable_samples** — `(user_id, source, metric, timestamp)` unique constraint; steps, HR, HRV, sleep stages from Health Connect/HealthKit.
- **biomarkers** — manually or CGM-sourced readings (blood pressure, glucose, etc.), `source` column (`manual` | `cgm` | `device`).
- **cgm_telemetry** — raw CGM stream, partitioned by month if volume warrants it.

## Nutrition (P5)
- **recipes** — 500+ seeded Indian recipes; `embedding vector` column (pgvector) for future semantic food-swap search. Not user-scoped — public read, admin-only write via service role.
- **meals** — user meal logs, `recipe_id` nullable FK, `vision_confidence` for OCR/photo-logged entries.
- **grocery_price_matrix** — vendor price snapshots, see `data_sources.md`/`scrapping_spec.md`. Not user-scoped.

## Workout (P6)
- **workout_sessions** — session metadata.
- **workout_sets** — per-set data, `pose_landmarks jsonb` from MediaPipe for form-check history.

## Gamification (P7)
- **karma_points** — ledger table (append-only), running balance computed via view.
- **habit_streaks** — current/best streak per habit type.
- **cohort_benchmarks** — materialized view, refreshed on schedule, anonymized/aggregated (no direct user_id exposure in the view's public columns).

## Social (P9)
- **squads**, **clubs**, **communities** — group entities.
- **squad_members**, **club_members** — join tables with composite RLS (`auth.uid()` must be a member to read squad content).
- **community_posts** — feed content, Realtime-subscribed.

## Predictive health (P10) / Visual analytics (P11)
- **biological_age_estimates**.
- **doctor_access_grants** — `granted_to` (doctor identifier), `expires_at`, scoped read-only RLS policy for the grantee.
- **progress_photos** — Storage object references, private bucket, signed URLs only.

## Monetisation (P13)
- **entitlements** — `user_id`, `tier` (`free`|`pro`|`elite`|`corporate`), `source` (`revenuecat`), `expires_at` — written only by the RevenueCat webhook Edge Function via service role; never client-writable.
- **push_tokens** — FCM device tokens, one row per device.

## Trust layer (P16)
- **abha_records** — ABHA ID, ABDM linkage metadata, FHIR sync status.
- **whatsapp_logs** — inbound/outbound message logs for the logging feature.
- **voice_logs** — vernacular voice transcription + extracted food entities.

## Compliance
- **erasure_receipts** — `receipt_id`, `anonymized_hash`, `deleted_at` — no personal data retained; generated by `delete_user_data`.

## Offline sync support (client-local, mirrored conceptually server-side)
- **pending_mutations** (Drift-only, not a Supabase table) — outbox of unsynced writes; see `architechture.md` §4.

## RLS pattern reference
```sql
alter table public.meals enable row level security;

create policy "owner_select" on public.meals
  for select using (auth.uid() = user_id);

create policy "owner_write" on public.meals
  for insert with check (auth.uid() = user_id);
```
Service-role-only tables (e.g. `entitlements`, `recipes` writes) explicitly omit a client-facing insert/update policy so only Edge Functions (service role, which bypasses RLS) can write.
